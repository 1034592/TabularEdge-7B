TabularEdge 运行指南

本地离线表格智能助手 · 模型 TabularEdge-7B（Q4_K_M，4.36 GiB）· 适配 i7-11800H + RTX 3050 Laptop 4GB + Excel 2019

1. 三步开始

  1. 双击 启动TabularEdge.bat（或直接双击 TabularEdge.exe）。右上角圆点变绿、显示“就绪”即可使用（首次加载模型约 10–30 秒）。
  2. 左侧默认已打开 test_cases 文件夹；顶部“示例场景”下拉框选一个场景，指令会自动填好。
  3. 按 Enter（或“解析指令”）→ 看“我理解的是：……”和计划预览 → 点“▶ 一键执行” → 点“打开结果”。多步场景点“下一步指令”，程序已自动切到上一步的结果文件。
想重新体验？双击 重置示例表格.bat，10 个示例表格恢复原样，生成的结果和备份一并清掉。

2. 界面说明

区域作用
右上角 语言中文 / English 界面切换（指令本身中英文都能理解）
右上角 引擎“自动（GPU+CPU 混合）”：按空闲显存自动决定放多少层到显卡，其余走内存和 CPU；显存不够会自动减层重试，再不行退回纯 CPU。“纯 CPU”：完全不用显卡。状态栏显示当前放到显卡的层数和生成速度（tok/s）。
工作目录选择你自己的 Excel 文件夹（“选择…”或直接粘贴路径后回车）。只处理这个文件夹里的文件，越界路径一律拒绝。
输入框Enter 提交，Shift+Enter 换行。指令里提到同目录下的其它文件名（如“员工花名册”），会自动把它当参考表带进来。
我理解的是模型流式输出时最先给出的一句话摘要，用来快速确认它没理解错。
计划预览每一步要做什么（人话）。⚠ 标记的是高危步骤。模型拿不准时，上方会出现“需要你确认的地方”，可以改选另一种理解。
一键执行删除整行、去重、覆盖原文件三类操作执行前一定弹窗确认（这是代码里的硬规则，不依赖模型）。默认结果另存为 *_处理后.xlsx，原表不动；如果你要求覆盖原文件，会先自动备份到 _backup 文件夹。
结果列出生成/修改的文件，双击或“打开结果”直接用 Excel 打开；“打开所在文件夹”定位到文件。

4. 实机测试结果

项目结果
10 个场景 / 28 步，逐步与人工标准答案比对算出来的结果（列值、条件格式命中的格子、拆分文件）27 / 28 步一致；9 / 10 个场景全程一致。不一致的一步是场景 2“中英文括号连同内容去掉”：模型只写了圆括号的正则，方括号【】等没有清掉（正则提取 / 正则清洗是模型的弱项）。提取类公式找不到时统一留空（自动包 IFERROR），这是与指令措辞无关的结构性规整。
标准答案本身的校验10 个场景全部用独立 Python 逐行核对通过；1,400+ 个公式与 LibreOffice 实算结果一致（含 Excel 2019 改写后的 INDEX/MATCH、MAXIFS、数组公式）
高危操作删除整行 / 去重 / 覆盖原文件 全部弹窗确认（实测 6 次弹窗）；覆盖前自动备份到 _backup
歧义追问“把空的都给我删咯”：批量测试时模型追问“删整行全空的，还是删备注为空的？”；界面测试那次没追问、直接按“整行全空”理解，但删除前照样弹窗。追问不是 100% 稳定。
速度（自动模式：CUDA，28 层里 21 层放显卡，其余走 CPU）生成 16.8–17.0 tok/s，显存占用 3.5 / 4.0 GB；“我理解的是”摘要中位数 1.6 秒（冷启动首条约 4 秒），完整计划中位数 7.7 秒（最长 26 秒）
速度（纯 CPU 模式，8 线程）生成 8.5 tok/s；摘要 6–9 秒，完整计划 18–30 秒；结果与 GPU 模式一致（实测 5 步全部通过）
引擎容错程序被强制结束时，推理引擎随之退出、显存立即释放（Windows 作业对象）；显存不足时自动减层重试，再不行退到 Vulkan / CPU
说法有讲究：本模型对“一句话一件事、写清列名”的指令最稳。下面这些在测试中需要换说法才对：
  • 档位/阶梯查找：口语“找不超过净销售额的最大档位”会被当成精确查找（全部查不到）。写成 VLOOKUP(净销售额,提成档位!A:B,2,TRUE) 就对了。
  • 新建列后紧接着按它汇总，最好分两句说（同一句里模型会把“采购金额”汇总成“单价”）。
  • “离职的人全删了”会被理解成 部门=离职；说成“备注含‘离职’的行删了”就对了。删除前的确认弹窗会写明删除条件，看到不对点“否”即可。
  • “括号符号去掉、里面的字保留”模型会连内容一起删；需要保留内容时，请先把要的信息提取成新列。
  • 纯行列转置（整表 TRANSPOSE）不在当前操作集里；场景 9 用“大区 × 月份”交叉矩阵实现交叉汇总。

操作实测说明
在左侧选中大表0.2–0.3 秒显示表结构只读表头和前 200 行；行数取自文件自带的尺寸信息。以前会整表载入，界面卡死
输入指令后按回车首字 0.2–0.5 秒，“我理解的是”约 1–3 秒表格分析在后台线程完成；选中表格、打字停顿时，程序已在后台把表结构预先送进模型
小表从大表匹配（2,000 行名单 × 76 万行大表）约 23 秒，内存不到 100 MB大表流式扫描：只保留名单里出现过的代码；进度显示在状态栏，界面全程可操作
界面最长卡顿0.1 秒左右Windows 要卡 5 秒才会判“未响应”
推荐用法：左侧选中小表（要补信息的名单），在指令里点名大表，例如：
从单位名录_76万行里按统一社会信用代码匹配单位详细名称和单位规模，匹配不到的写未匹配
信用代码前后有空格、或一边是数字一边是文本时，也能匹配上。
  • 对大表的匹配结果写成值，不写公式：如果写成活公式，就得把 76 万行整表复制进结果文件，结果文件会变成上百 MB，Excel 也会很卡。计划预览里也会这样标明。
  • 大表本身不能直接逐格修改（例如“把大表里状态为正常的筛出来”）：要在 Python 里完整载入这 1,900 万个单元格，需要十几 GB 内存，耗时十几分钟。程序会在执行前提示，不会去尝试。这种需求请先在 Excel 里用筛选把需要的部分另存成小表，再交给 TabularEdge。
  • 阈值：2 MB 以上的文件用流式读取；参考表超过 20 MB 或 150 万个单元格，按大表方式匹配；主表超过 300 万个单元格，不做逐格修改。

6. Excel 2019 兼容说明

本机是 Excel 2019（Home & Student），没有 XLOOKUP / FILTER / UNIQUE 等动态数组函数。程序会自动识别版本并改写公式：
  • XLOOKUP 精确查找 → IFERROR(INDEX(…,MATCH(…,0)),缺省值)；档位（近似）查找 → INDEX/MATCH + MAXIFS，不要求档位表排序。
  • 不重复清单（UNIQUE）→ 经典数组公式 INDEX/MATCH/COUNTIF，预留 20 行，源表新增供应商会自动出现。
  • 筛选到新表（FILTER）→ 写入数值；TEXTBEFORE、REGEXEXTRACT 等无法改写的函数 → 写入计算结果，日志里会注明。
升级到 Microsoft 365 后，把 config.json 里的 "excel" 改成 "365" 即可直接写新函数。

8. 常见问题

  • 一直显示“正在启动”：看 %LOCALAPPDATA%\TabularEdge\logs\llama-server-*.log；或用“纯CPU模式启动.bat”。
  • 提示端口被占用：把 config.json 的 port 改成别的数字。
  • 结果文件打不开 / 被占用：先在 Excel 里关掉同名文件再执行。
  • 模型理解错了：换个更具体的说法（说清列名、条件、放到哪张新表），或拆成两条指令分步做；每条结果都可以接着处理。
